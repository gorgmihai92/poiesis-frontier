# Frame (always first)

Decide what kind of problem it is before generating anything. The kind decides whether frontier fits and how
experiments are run (Kurtz & Snowden 2003; van Beurden et al. 2011).

| Kind | Cause and effect | How to act | Frontier? |
|---|---|---|---|
| **Simple** | clear and agreed | sense, categorise, respond: use the known practice | no: say so and point to the known practice |
| **Complicated** | stable, but needs analysis or expertise | sense, analyse, respond | rarely: send the question to research or insight first |
| **Complex** | seen only in hindsight; many interacting agents | probe, sense, respond: several small probes, amplify what works | yes: this is where frontier belongs |
| **Chaotic** | none visible | act, sense, respond: stabilise first | not yet: stabilise, then come back |
| **Disorder** | not known which of the above | split the problem into parts and frame each | after splitting |

Write in the frontier note, in a few lines:
1. **The question** in one sentence, and what the answer will be used for.
2. **Starting points:** each tested insight, scenario or gap, with reference and how it was tested.
3. **Kind**, with the reason (which observations put it there). Parts of one problem can be of different kinds.
4. **Constraints:** what cannot change (budget, people, ethics, time). Experiments must fit inside them.
